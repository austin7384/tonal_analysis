OVERVIEW
--------
build_phrase_matrix.py is the Python stage of the v1 GST-style phrase-ranking
pipeline. It adapts the Gentzkow-Shapiro-Taddy (2019) phrase-partisanship
methodology to identify which bigrams drive the LLM Readability score on the
project's abstracts. The script reproduces the Hengel N=9,117 analysis sample,
binarizes abstracts into top/bottom Readability quintiles, tokenizes them into
bigrams, applies frequency filters, and writes a sparse phrase-count matrix in
three CSV files for the downstream R `gamlr` Poisson lasso stage. The output
is a face-validity diagnostic — given the LLM rubric, which phrases is the
model keying on for "Readability"?


INPUTS
------
data/processed/llm_evaluated/clean_evaluations/merged_evaluations.csv
    Author-level merged file (~26,481 rows). Columns consumed:
      ArticleID, Journal, Language, Title, Abstract, Readability


OPERATIONS
----------
- Loads merged_evaluations.csv.
- Restricts to the four main journals (AER, ECA, JPE, QJE).
- Drops non-English abstracts.
- Removes errata / corrigendum titles via case-insensitive regex.
- Deduplicates to article-level (one row per ArticleID).
- Drops rows missing Abstract or Readability.
- Computes the 20th and 80th percentiles of Readability.
- Tags articles at or below p20 as group=0 (low Readability); at or above p80
  as group=1 (high Readability). Drops the middle.
- Tokenizes each abstract: lowercase, strip non-alphanumeric (keep apostrophes
  and whitespace), drop single-character and pure-digit tokens, keep
  stopwords, generate bigrams via adjacent-token pairing joined with `_`.
- Counts each bigram's per-document and total-corpus frequency.
- Keeps bigrams with n_docs >= 5 AND total_count >= 10.
- Assigns sequential phrase_idx ordered by descending total_count.
- Builds sparse triplets (doc_idx, phrase_idx, count) for nonzero entries
  using the surviving vocabulary.
- Writes documents.csv, phrases.csv, phrase_counts.csv to the staging dir.


OUTPUTS
-------
data/processed/sg_phrase_analysis/documents.csv
    One row per article in the top+bottom-quintile subset.
    Columns: doc_idx, ArticleID, group, Readability, total_bigrams

data/processed/sg_phrase_analysis/phrases.csv
    One row per surviving bigram.
    Columns: phrase_idx, phrase, n_docs, total_count

data/processed/sg_phrase_analysis/phrase_counts.csv
    Sparse-triplet representation of the doc x phrase count matrix; one row
    per nonzero (doc, phrase) pair.
    Columns: doc_idx, phrase_idx, count


SECTION-BY-SECTION DETAIL
=========================

Section 1 - Load and filter to Hengel analysis sample
-----------------------------------------------------
What it does:
  Reads merged_evaluations.csv (author-level, ~26,481 rows) and applies the
  exact filter chain that produces the canonical N=9,117 article-level
  analysis sample. Each filter prints a row count so the cumulative drop is
  visible at runtime.

Filters applied, in order:
  1. Journal in {AER, ECA, JPE, QJE} - drops P&P, RES, and any non-main
     journals (Stata-pipeline equivalent: `drop if Journal==5` plus the main-
     journal restriction in correlation_matrix.py:63).
  2. Language == 'English' - drops non-English-language articles.
  3. Title does NOT match any of:
        ['corrigendum', 'erratum', ': a correction', ': correction']
     (case-insensitive substring match). Mirrors EXCL_PATTERNS at
     hengel_data_cleaning.py:56 and correlation_matrix.py:59.
  4. drop_duplicates('ArticleID') - collapses author-level rows to article-
     level. Abstract and Readability are constant within ArticleID, so any
     row's value is valid; pandas keeps the first occurrence.
  5. dropna on Abstract and on Readability after coercing Readability to
     numeric.

Why this filter chain:
  The same chain is already used in correlation_matrix.py and llm_summary_
  stats.py. CLAUDE.md notes "the 4 manually-flagged ECA articles" excluded
  from the main sample - those drop out implicitly via the dropna step
  because they have missing LLM evaluations, so no explicit ID list is
  needed. The chain is provably correct because it lands at exactly 9,117.

Most-recent run trace:
  Raw rows (author-level):                    26,481
  After main-journal filter (AER/ECA/JPE/QJE): 16,065
  After English filter:                        16,062
  After errata-title filter:                   16,055
  After dedupe to article-level:                9,117
  After dropping missing Abstract/Readability:  9,117

Edge cases:
  - The DtypeWarning printed at load time is harmless: three trailing columns
    (Metrics, Accepted_by, Department) have mixed dtypes, but those columns
    are not consumed.
  - Readability is stored in merged_evaluations.csv as plain numeric; the
    explicit pd.to_numeric is a defensive coerce (any malformed cell becomes
    NaN and is dropped).


Section 2 - Quintile binarization on Readability
------------------------------------------------
What it does:
  Computes the 20th and 80th percentiles of Readability on the 9,117-article
  sample, splits the sample into bottom/top groups using the predicates
  Readability <= p20 and Readability >= p80, and discards the middle.

Why quintile (locked decision):
  GST's groups are categorical (R vs. D) - quintile is our manufactured
  binary contrast. Quintile balances score-gap contrast against per-group N
  better than decile (too thin at N=9,117) or tertile (too soft a contrast).
  See project_gst_phrase_ranking.md for the full decision log.

Most-recent run trace:
  Readability quintile cutoffs: p20=6.0, p80=8.0
  Bottom-quintile articles (group=0): 3,635
  Top-quintile articles    (group=1): 3,069
  Quintile-subset total:              6,704

Edge cases / known issue:
  Readability is integer 1-10 with heavy mass at scores 6, 7, 8. p20 and p80
  both fall on integer values, and the <= / >= predicates therefore sweep in
  the entire boundary mass:
    Readability distribution (article-level):
      score: 2  3   4    5    6    7    8    9   10
         N:  4 110 557  760 2204 2413 2200 866   3
    Bottom (<=6):  4 + 110 + 557 + 760 + 2204 = 3,635 (~40% of sample)
    Top    (>=8):  2200 + 866 + 3            = 3,069 (~34% of sample)
  Result: groups are larger and asymmetric versus the conceptual 20/20 split.
  v1 retains the asymmetric cut as-is. Robustness runs (planned) will explore
  tighter cuts such as <=5 vs. >=9 (~1,431 vs. ~869) for sharper contrast and
  cleaner balance. Same boundary-mass issue likely recurs whenever the
  pipeline generalizes to other 1-10 integer-scored criteria.


Section 3 - Tokenize abstracts to bigrams
-----------------------------------------
What it does:
  For each abstract in the quintile subset, produces a multiset (Counter) of
  bigrams.

Tokenization rules:
  1. Lowercase the abstract.
  2. Replace any character not in [a-z0-9'\s] with a space, via
     re.compile(r"[^a-z0-9'\s]"). Apostrophes are preserved so that
     contractions ("don't", "doesn't") survive as single tokens.
  3. Split on whitespace.
  4. Drop tokens of length <= 1 OR tokens that are entirely digits
     (`t.isdigit()`).
  5. Stopwords are explicitly RETAINED. Tonal moves require them
     ("we_show", "may_be", "it_is", "can_be"); removing stopwords would
     destroy the very phrases the analysis aims to surface.
  6. Bigrams are built with `zip(tokens, tokens[1:])` and joined with an
     underscore (e.g., "we_show", "of_the").

What this section does NOT do:
  No stemming, no lemmatization, no part-of-speech filtering. v1 keeps
  surface form so the output table reads naturally.

Output of this section (in memory):
  doc_bigrams: list[Counter[str, int]] of length len(sample) (= 6,704 in
  the most-recent run). Each Counter is the bigram bag for one abstract.


Section 4 - Phrase filtering: vocab over the quintile subset
------------------------------------------------------------
What it does:
  Builds the surviving vocabulary by aggregating per-document Counters:
    vocab_total[p]  = total occurrences of bigram p across the quintile
                       subset
    vocab_n_docs[p] = number of documents containing bigram p at least once
  Keeps only bigrams where:
    vocab_n_docs[p] >= MIN_DOCS  (5)
    vocab_total[p]  >= MIN_TOTAL (10)
  Both thresholds must be satisfied. Survivors are sorted by descending
  total_count (ties broken alphabetically) and assigned a sequential
  phrase_idx starting at 0.

Why these thresholds (locked decision):
  GST uses (>=10 uses, >=10 unique speakers) on a 287M-instance corpus.
  Our corpus is roughly two orders of magnitude smaller, so the v1 spec
  relaxed thresholds to (>=5 docs, >=10 total). This keeps low-frequency-
  but-meaningful tonal phrases from being filtered out before they reach
  the lasso, while still excluding singleton noise.

Section 5 - Build sparse triplets and document metadata
-------------------------------------------------------
What it does:
  For each document, intersects its bigram Counter with the surviving
  vocabulary, keeps only surviving bigrams, sums their counts to compute
  total_bigrams (per-document corpus length, post-filter), and emits one
  triplet (doc_idx, phrase_idx, count) per nonzero (doc, phrase) pair.

Three DataFrames assembled:
  documents:
    Columns: doc_idx, ArticleID, group, Readability, total_bigrams
    One row per article in the quintile subset.
  phrases:
    Columns: phrase_idx, phrase, n_docs, total_count
    One row per surviving bigram.
  phrase_counts:
    Columns: doc_idx, phrase_idx, count
    Sparse triplet representation of the doc x phrase matrix.

Why sparse triplets (locked decision):
  At 6,704 docs x 9,670 phrases = ~64.8M cells, a dense CSV would balloon to
  hundreds of MB. The sparse representation collapses to ~302K rows
  (~3.2 MB) because most (doc, phrase) cells are zero. R reads this format
  directly via Matrix::sparseMatrix(i = doc_idx + 1, j = phrase_idx + 1,
  x = count) - the `+1` is the only adjustment needed since R is 1-indexed.

The total_bigrams column on documents:
  Stored for use as a Poisson exposure offset in the R lasso. It is the
  count of phrase tokens kept per document AFTER the vocabulary filter, not
  the raw bigram count - the raw count is irrelevant once filtered phrases
  are dropped from the regression matrix.

-------------------------
What it does:
  Creates the staging directory if it does not exist
  (`OUT_DIR.mkdir(parents=True, exist_ok=True)`) and writes the three CSVs
  via pandas `df.to_csv(path, index=False)`. Prints one log line per file
  with the relative path and row count.
